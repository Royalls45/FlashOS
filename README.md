# FlashOS

Первый рабочий этап проекта по техническому заданию: WPF/MVVM-интерфейс для безопасного анализа съёмных накопителей.

## Возможности

- обнаружение готовых съёмных накопителей Windows;
- показ буквы/пути, имени, файловой системы, полного и свободного места;
- рекурсивный поиск `.iso`, `persistence.bat`, `.dat` и `ventoy.json`;
- отображение найденных файлов и путей;
- журнал событий;
- обработка недоступных каталогов, ошибок чтения и отключения накопителя;
- тёмный интерфейс;
- безопасный анализ `ventoy.json` и `persistence.bat` без исполнения;
- проверка QEMU и запуск ISO только после явного подтверждения;
- предпросмотр команды запуска с проверкой ISO и ресурсов VM;
- резервное копирование файлов отдельным сервисом.

Сервис читает `persistence.bat` и конфигурации только как найденные файлы: скрипты не запускаются, форматирование и изменения на накопителе не выполняются. Наличие `persistence.dat` не считается доказательством работающего Persistence.

## Запуск в Windows 10/11

1. Установить .NET 8 SDK или Visual Studio 2022 с рабочей нагрузкой **Разработка классических приложений .NET**.
2. Открыть `FlashOS.sln`.
3. Выбрать `FlashOS.App` запускаемым проектом.
4. Выполнить сборку и запуск (`dotnet build` / F5).

Сборка требует Windows target framework (`net8.0-windows`), поэтому в Linux без установленного .NET SDK и Windows Desktop targeting pack проверить WPF-компиляцию невозможно.

## Реализованные сервисы второго этапа

- разбор `ventoy.json` без изменения файла;
- проверка существования backend-файлов относительно корня накопителя;
- чтение `persistence.bat` как текста с предупреждениями о потенциально опасных командах;
- проверка доступности QEMU через `--version`;
- генерация предпросмотра команды QEMU с проверкой ISO и ресурсов;
- управляемый запуск QEMU через отдельный сервис;
- резервное копирование файла с уникальным timestamp-именем;
- отдельная документация по Persistence и критериям фактической проверки.
